## Notes

- Запуск тестів - лише `python -m pytest` із кореня проєкту. Bare `pytest`
  падає з `ModuleNotFoundError`, доки задача 6.1 не додасть шлях імпорту
  в налаштування pytest.
- Нові юніт-перевірки розширюють `tests/test_elastic_model.py`, а не
  створюють окремий файл на кожну вимогу: усі вони про поведінку того
  самого класу.
- doctest'и вимагають `email-validator` через `EmailStr` в обох прикладах.
- Профіль проєкту - `quality`, підхід до тестування `tdd`: для логіки
  спершу тест, потім реалізація. Для текстових правок README і метаданих
  TDD не застосовується.
- Три обмеження формату doctest описані в технічному дизайні. Порушення
  будь-якого з них валить прогін, і жодне не видно з документації:
  порожній рядок усередині блоку обриває приклад; порожній рядок перед
  закривальним фенсом обов'язковий; коротке ім'я класу помилки працює
  лише з прапорцем `IGNORE_EXCEPTION_DETAIL`.
- Реліз один, версія 0.3.0.
- Історія 7.0 мусила бути останньою серед 1.0-7.0: із моменту 6.0 doctest
  входить у звичайний прогін і сам стає частиною критерію «зелено» для
  матриці версій.
- Історії 8.0-13.0 (2026-10-14) виправляють знахідки код-рев'ю реалізації.
  Порядок 8.0-12.0 задають залежності: README (12.0) описує вже
  реалізовану поведінку. Історія 13.0 повторює перевірки 7.0 на новому
  коді й мусить бути останньою.
