# elasticmodel — правила проєкту

## `ElasticModel` лише розширює `BaseModel`

Уся поведінка `pydantic.BaseModel` в `ElasticModel` лишається такою самою, як у pydantic.
Бібліотека лише додає нове поверх неї: часткове створення через `elastic_create`, `NotLoadedFieldError`, облік завантажених полів, `elastic_extra`, shallow/deep перевірку.
Код, уже налаштований на `BaseModel`, після переходу на `ElasticModel` працює без змін, а нове доступне окремими методами `elastic_*`.

- Кожну зміну логіки `ElasticModel` звіряй із `BaseModel`: для того самого класу й тих самих даних результат pydantic — еталон.
- Розходження з pydantic допустиме лише там, де `ElasticModel` свідомо додає можливість, і воно описане в README.
- Еталон перевіряй прогоном на тому самому класі, оголошеному на `BaseModel`, а не з пам'яті; документовану поведінку pydantic — через Context7.
- Тест поведінки, що має збігатися з pydantic, порівнює результат із самим pydantic (зразок — `test_alias_rules_match_pydantic`), а не з вписаним вручну очікуванням.
- Знайдене розходження, яке не є свідомим розширенням, — дефект. Його виправляють або явно виносять у Out of Scope PRD, а не лишають мовчки.

Причина: README обіцяє «просто заміни `BaseModel` на `ElasticModel`».
Кожне непомічене розходження ламає цю обіцянку для того, хто переводить на `ElasticModel` свою робочу модель.
